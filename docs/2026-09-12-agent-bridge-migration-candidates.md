# 旧 OpenCode Worker 的迁移候选清单

2026-09-12。仅供用户评估，未修改 Agent-Bridge 或旧插件代码。对照当前已安装 Agent-Bridge 0.1.0 / f8f544c6b0af，以及保留的 OpenCode Worker 0.3.2。目标是减少重复执行、误判和操作成本，保留原生 Agent 能力；不增加主控重做任务或强制重复测试。

## 建议优先考虑

| 编号 | 候选 | Agent-Bridge 当前已有 | 真正缺少的部分 | 最小改动边界 | 代价 |
| --- | --- | --- | --- | --- | --- |
| A | 重启后仍能识别同一个请求 | 同一实例中有 request_id 去重、参数冲突拒绝；会话与任务能持久化 | 请求 ID 绑定没有落盘，重启后相同请求可能再次执行；已用两个独立进程和 fake Agent 复现 | 保存请求与任务/轮次的绑定，恢复时读取；保留参数冲突检测；明确保留期，不能任务删了就偷偷当新请求；仅做短暂状态协调，不限制任务执行并发 | 中：需覆盖保存、恢复与清理，不是复制一段旧代码即可 |
| B | 非正常结束的显著提示 | get_result 有 status、stop_reason、warnings | max_tokens、max_turn_requests、refusal 都可能显示 completed，警告为空；主控只看状态容易遗漏 | 保持 completed 表示流程结束，同时补可读警告/处理建议；不自动重试、不重跑测试、不做质量评审，也不额外调用模型 | 小：基于协议已提供字段处理 |

A 的验收：一个任务完成后重启 Bridge，再用同一 ID/参数查询或重试，返回原任务；更改参数仍拒绝。边界是防重复派发，不保证所有外部副作用 exactly-once。

B 的验收：正常结束不报警；长度上限、轮次上限、拒绝分别提示真实原因。空文字但已有文件交付不能一概判失败。主控据此决定是否续接，不能自动无限重试。

本次补充验证：让 fake Adapter 分别返回 end_turn、max_tokens、max_turn_requests、refusal。四者均为 completed，后三者 stop_reason 如实保留，但 warnings=[]、hint 相同。这是信息突出程度的缺口，不是声称 Bridge 丢失了结束原因。

## 有明确使用需求时再考虑

| 编号 | 候选 | 价值与缺口 | 建议触发条件 | 不做什么 |
| --- | --- | --- | --- | --- |
| C | 分清请求、已设置、原生记录中的模型与推理档 | Bridge 对 OpenCode 的 observed 字段是适配器设置值；旧插件有原生消息核对。能帮助解释模型/档位切换及结果差异 | 出现模型不符，或开始正式比较模型/资源消耗时 | 不强制最高档，不因兼容映射立即终止任务，不每轮导出全部会话 |
| D | 每轮资源消耗的统一口径 | Bridge 已返回 usage，但本次 OpenCode ACP 的 used 是上下文占用相关读数，不能简单累加当总 token；不同 Worker 口径不同 | 确实要依据消耗选择组合或制作成本对比时 | 只采集可得到的数据，区分本轮/累计/上下文/估算费用；未知不填零；不抓取所有提供商账单。旧插件的可见消息统计也不是全账单真相 |
| E | 子任务失败与未结束提示 | 旧插件借助 OpenCode 原生 API 汇总父子树；Bridge 未提供同等完整的通用树摘要 | 实际使用内部多 Agent 后，出现父 Agent 提前回复或遗漏子任务错误时 | 不限制子代理数量/深度，不移植固定 OMO 角色，不要求主控复做子任务。仅在可获得可靠树状态时提示，否则标注未知 |

C、D 建议做成同一份可选运行详情，避免两套采集。E 跨产品实现代价最大：不要为了单个 OpenCode 场景把通用桥接器变成专用调度平台。

## 不需要搬：现有功能足够

| 旧插件能力 | Agent-Bridge 当前情况 | 结论 |
| --- | --- | --- |
| 同会话返工/追加需求 | dispatch_task 带 session_id 已支持，两轮真实试用通过 | 直接用 |
| 等待超时与任务结束分开 | wait_task 有超时、状态、静默时长 | 直接用 |
| 取消与结束会话 | cancel_task、end_session，ACP 取消及必要的进程回收已有 | 不重写；进行中取消尚未做本机真实验收，可在有需要时验证 |
| 保存结果、日志、文件变更 | get_result、get_transcript、分页及文件变更已有 | 直接用；不重造结果仓库 |
| 指定模型与档位 | 已支持，并报告映射结果与部分警告 | 保留灵活选择，C 只补来源说明/诊断 |
| 主控查看交付 | 官方技能已经要求查看改动和相关检查 | 不另加验收服务；证据足够就交付，只对具体疑点补检查 |

## 不搬或只归档

- 文件与命令白名单、只读模式禁 Shell、禁用原生 MCP/Skills。
- 全局单活跃任务、最多两个子代理、禁止继续委派。
- 强制 OpenCode Go、固定 OMO 角色与统一最高推理档。
- 旧插件的“同一命令后来成功才算恢复”等工具错误判断：可能把已通过另一种方法解决的错误误报为未解决。保留错误事实即可，不照搬判定器。
- 每轮复制 runner/guard 防插件缓存被删：这是旧插件执行架构需要，当前 Bridge 安装/进程结构不同，没有证据表明需要同一套方案。
- 全量改动前后快照：已有 Git 和文件变更记录时不增加一套复制机制；确有非 Git 恢复需求再讨论。

旧 fake backend、生命周期/取消/续接测试的“场景”值得保存。A/B 真正开发时，把相关场景改写为 Agent-Bridge 测试；不把旧测试框架整体接进去，也不在每次用户任务结束后重复运行这些开发测试。

## 我的建议

第一批只选 A+B；C+D 等开始比较资源消耗时一起做；E 暂缓；其余不搬。优先小范围上游改进，不新增代理包装层、不并行维护两套调度器。当前并未执行任何改造。
