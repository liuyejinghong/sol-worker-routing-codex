# OpenCode Worker 最终方案：单次 run，程序内部等待

日期：2026-09-08。状态：原型验证完成后，已按用户授权安装正式插件 0.2.0；现有任务和 heartbeat 未修改。

## 结论

默认使用一个 `run` 工具完成派发和结果回收。等待期间由普通程序读取状态，主代理不参与空检查；结果返回后，主代理继续验收。保留当前轮待工具返回，不依赖唤醒已经结束的会话。

隔离原型已通过真实验证：一条 run 请求持续 150.593 秒，期间没有主代理消息或主线程计量更新；返回后主代理实际读取文件，标记正确。模拟测试覆盖失败、中断、超时窗口、去重和返工。

## 正常流程

```text
Codex 准备任务包并调用 run
    → 插件派发 Muse
    → 插件程序等待（不请求主模型检查状态）
    → 完成、失败、需要处理或等待窗口到期时返回
    → Codex 验收，或明确继续/返工
```

不先调用一次 status 再 start 再 wait。run 本身执行已有环境检查和请求去重。需要返工时，使用 `followup` 的等待参数，在同一会话中完成返工和回收。

## 工具契约

| 工具 | 用法 |
|---|---|
| `run`（新增） | 接收原 start 任务包和 wait_seconds，派发后在程序内部等待 |
| `followup` | 增加 wait_seconds；大于零时在同一调用内等待返工结果，零保留原立即返回行为 |
| `wait` | 保留给恢复和显式继续等待，支持较长窗口 |
| `start` | 保留显式后台模式；它仍不注册原会话唤醒，不作为普通任务的默认入口 |
| `status` / `cancel` | 处理用户查询、恢复和明确取消 |

原型 wait_seconds 上限及默认 run 窗口为 300 秒，宿主 MCP 超时为 360 秒。实测 Code Mode 外层使用 yield_time_ms=300000；正式使用时外层等待应覆盖内部窗口并预留交接余量，不能沿用默认 30 秒提前返回。直接调用 MCP 的宿主不需要 Code Mode 设置。

等待窗口是有限的。本次实测 150.6 秒，不宣称已验证数小时的连续请求。任务超过窗口时返回 `wait_expired=true`、`finished=false`，主代理必须继续等待或明确移交已绑定的跟进，不能宣称后台将自动唤醒原会话。

## 请求、中断和权限

- 同一请求重试使用相同 request_id；run 复用已有任务，不重复启动。
- 重复访问旧 request_id 时返回对应旧轮次的存档，不把较新 followup 的结果当成旧请求结果。
- RPC 等待中断只停止等待，不盲目取消 Worker。用户要停止执行时调用 cancel；中断等待不能被标记为完成。
- 失败、cancelled、needs_attention 提前返回；unknown 且 finished=false 返回恢复需求，不能释放文件所有权。
- `completed` 仍表示执行结束，主代理验收独立进行。
- 保留现有路径、精确命令和外部数据授权规则。长等待不会扩大权限。
- 主代理准备交接后才调用 run。没有结果或明确托管跟进时，不结束当前轮并承诺之后自动处理。

## 验证

### 程序与 MCP 契约

13 项本地测试通过；独立的模拟 MCP 测试通过以下场景：

1. 成功和模型失败及时返回。
2. 相同请求不重复派发。
3. 同会话返工可在一个调用内等待。
4. 旧请求返回旧轮次。
5. 窗口到期不冒充完成。
6. RPC 取消停止等待，Worker 仍保持未结束状态。
7. 明确 cancel 后停止 Worker 并返回取消状态。

### 真实执行与计量观测

使用本机 Codex 0.153.4 的隔离 App Server 和 ephemeral 测试会话，记录官方 `thread/tokenUsage/updated` 通知。没有使用该服务器冒充原 App 会话唤醒；这里验证的是受控会话内的单次工具请求。

- Worker：OpenCode 1.18.29，Sisyphus，`opencode-go/muse-spark-1.3-contributor`。
- 工作内容：运行合成 Python 脚本，sleep 130 秒后写入测试标记。没有业务数据。
- run 开始：14.867 秒；返回：165.460 秒；持续 150.593 秒。
- 主线程计量更新：165.461、171.476、179.567 秒，共三次；各次 last 用量相加与 final total 一致。
- 三次更新对应派发工具、读取产物、最终答复；run 等待区间内无额外计量更新或主代理消息。
- 主代理真正执行只读文件读取，输出与预期标记一致，退出码为零；脚本未被修改。
- Worker 任务已完成，专属服务已关闭。

这里观察的是宿主报告的主线程计量，不是独立的计费审计。完整流程累计 input_tokens=58959，其中 cached_input_tokens=38656，output_tokens=401；这些是三次模型处理上下文与结果的用量，不是状态等待的用量。

本轮为明确观测边界，在测试进程中关闭了无关插件、MCP、memory 和 hook，未修改全局设置。因此不能把这个总量与先前完整配置下的十几万输入直接算成节省比例。也不包含 Muse 或其他独立服务的费用。
