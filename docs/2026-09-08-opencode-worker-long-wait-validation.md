# OpenCode Worker 单次长等待验证

日期：2026-09-08。结论：隔离探针验证了单次长等待、Worker 完成后返回、主代理继续读取并验收产物。正式插件、现有任务和 heartbeat 未修改。

## 验证目标与边界

原会话已结束后的完成唤醒受当前 App 的控制入口限制，见 [宿主接入验证](2026-09-08-opencode-worker-completion-wakeup-validation.md)。本次验证另一种模式：保持当前轮待工具返回，由程序检查 Worker 状态，避免主代理每 30 秒重新查询。

此模式不能称为“会话彻底结束后的异步唤醒”。它依赖当前宿主继续保持工具调用，未验证 App 关闭后恢复，也未验证数小时等待。

## 探针设置

- 使用已安装插件的独立临时副本，未重新安装该副本。
- 临时副本的 wait 上限从 30 秒提高到 180 秒。
- 仅对测试 Codex 进程配置 MCP 工具超时 210 秒，不写全局配置。
- 实际 Worker 使用本机 OpenCode 1.18.29、OMO Sisyphus 和 Go Muse Spark 1.3 Contributor。
- 后台命令只运行合成脚本：sleep 后写入已知标记，首轮 65 秒，后两轮 95 秒。
- Codex 使用 App 自带 0.153.4 的 ephemeral 测试会话；每轮只发起一次 start、一次插件 wait。wait 返回后，主代理用只读 shell 读取结果文件。
- 所有工作目录和任务状态均在 `/private/tmp/ocw-long-wait-i0pl39rk`，没有访问 Tokens 项目。

## 三轮结果

| 设置 | 单次 MCP wait 实际时长 | 等待期间可见主代理消息 | 主代理对外层执行的报告 |
|---|---:|---:|---|
| 延长 MCP 等待，外层默认 | 112.314 秒 | 1 条“仍在等待” | 未给出续等次数 |
| 再要求静默，但外层仍默认 | 115.397 秒 | 0 | 外层提前返回，续等 2 次 |
| 同时延长外层 exec yield | 119.886 秒 | 0 | 未提前返回，续等 0 次 |

三轮都完成真实任务，Provider/模型身份正确，产物标记匹配。事件记录证明每轮只调用了一次 MCP wait；主代理在该调用返回后实际读取结果，读取命令退出码为 0。最后一轮的合成脚本还做了内容一致性核对。

需要区分证据强度：CLI JSON 记录 MCP 调用起止与消息/命令事件，不直接暴露外层 Code Mode 的 exec/wait 调用。因此上表外层续等次数是执行代理报告，不是独立逐次请求计数；不能据此宣称已精确计量等待期间为零 token。

## 关键发现：需要三层等待时间一致

只改插件等待上限还不够。MCP 请求虽然一直在执行，外层 Code Mode 包装器仍可能按默认时间提前返回，要求主代理再续等。

最后一轮使用：

```text
插件 wait.timeout_seconds = 180
宿主 MCP tool_timeout_sec = 210
调用 wait 的 functions.exec：yield_time_ms = 180000
```

外层 exec 的设置形式为：

```javascript
// @exec: {"yield_time_ms": 180000, "max_output_tokens": 1500}
const result = await tools.mcp__ocw_long_wait_probe__wait({
  task_id: "测试返回的 task_id",
  timeout_seconds: 180
});
text(result);
```

这里的工具名属于临时探针，不是已安装插件的新接口。不同宿主可能直接调用 MCP、没有这一层 Code Mode；正式工作流应按实际调用方式处理。

## 对 token 结果的解释

三轮完整主代理流程的 input_tokens 分别为 196931、193824、140944，但输入、缓存命中、模型行为均不同。这些数字包括派发、工具交接、读取和最终验收，不是等待阶段的独立用量，不能直接换算净 token 节省或费用比例。

本次可确认的是：延长外层等待后，观察到单次约两分钟的 MCP 等待，期间没有中途主代理消息，且执行代理报告没有额外续等。这个结果支持继续实现“当前轮长等待”优化；不支持宣称任意时长、任意宿主下完全零唤醒。

## 后续落地范围

1. 同步修改插件 wait 上限和宿主 MCP 超时，保留明确上限和提前返回终态的行为。
2. 工作流在需要等待的 Code Mode 调用中匹配外层 yield 时间，并避免无变化的进度说明。
3. Worker 未结束且跟进未托管时，不结束主代理响应。达到等待上限后明确继续等待或移交已绑定跟进，不能假装已建立完成回调。
4. 正式更新前补验证长等待中的用户中断与取消，以及失败提前返回。长等待不改变文件所有权、授权或验收语义。

完整精简证据见 [JSON](2026-09-08-opencode-worker-long-wait-evidence.json)。三个探针任务均已结束，专属服务端口均无监听；正式插件仍保留原 30 秒等待上限。
